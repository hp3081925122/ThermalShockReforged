# SB-021：Blasphemer 核心样本加入被取消后的奖励边界

状态：待复现的疑似奖励丢失边界；尚未判定为模组缺陷。

固定第99批快照 `00bbd5801c3d373d0d239637de9dd69f2f5974d5`。当前迁移实现 `BlasphemerProcessEntity` 在第134个服务端 END 阶段播放取物音效，并通过 `MachineContent.drop` 创建一个 `infected_core_sample` 的 `ItemEntity`，随后只检查一次 `level.addFreshEntity` 的返回值。加入被拒时记录警告，但不会重试；任务仍会在第180个阶段完成机器状态转换并移除。

疑点来源：迁移文档承诺流程在第134阶段产出一枚核心样本，却没有明确外部 `EntityJoinLevelEvent` 取消时是应尊重取消并接受无产物，还是应在后续阶段重试。强制重试可能破坏其他模组有意拦截该产物的行为，直接接受丢失则可能让一次性机器流程消耗资格却不给奖励。

待验证范围：在独立服务端 GameTest 中只取消该锚点、该物品类型的 `EntityJoinLevelEvent`，确认第134阶段无物品、第180阶段仍完成；解除监听后再验证正常流程仍只生成一枚样本。还要核对原 MCR 字节码和迁移契约是否存在取消后的补偿或重试语义。测试不得把其他实体的加入取消混入结果。

预期与实际：预期尚待原件与运行证据共同确定；当前静态实际是单次提交、失败仅英文警告、任务继续。没有据此修改生产代码，也不能把静态疑点写成已确认缺陷。

影响范围：仅涉及 Grand Blasphemer 一次性流程的核心样本加入被外部事件取消的边界；正常无取消路径由其他用例覆盖时，不能关闭本记录。

证据：生产快照与源码路径见上文；实际运行日志、测试源码哈希和原件字节码定位待补。该记录必须在疑点关闭、确认缺陷或确认依赖语义后保留，并链接到 `suspected-bugs.md`。

原件核对与关闭依据：原GrandBlasphemerOnBlockRightClickedProcedure.java第119至135行只调用一次addFreshEntity；原JAR的lambda$execute$2调用后pop返回值，无重试或补偿。目标同样单次提交，失败新增英文warn。第四轮真实服务端取消样本加入后无物品且过程完成，符合原件。该疑点关闭为原件已有的外部取消边界，不是迁移新增缺陷；强化可靠产出属于后续设计变更。
