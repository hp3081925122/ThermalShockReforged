# 服务端测试异常记录规则

每个确认缺陷或怀疑点立即建立独立 `SB-编号-主题.md`，并加入 [suspected-bugs.md](suspected-bugs.md)。同一排查发现不同根因或不同功能缺失时，分别编号；共用日志也不能合并为笼统的一条。

每份记录至少包括：状态、固定提交与环境、原功能依据、触发和边界、预期与实际、源码定位、复现日志与SHA256、测试辅助与SHA256、影响范围、后续处理。静态疑点尚无运行证据时明确标待验证，不填造通过或失败结果。

状态区分：待核原件、待复现、已确认本模组缺陷、已确认依赖行为、旧快照迁移覆盖缺口、已关闭的测试夹具/预期问题、已修待回归、回归通过。不能把外部NeoForge问题归为模组业务实现错误，也不能把未迁功能说成已运行通过。

误报也保留独立文档，写清证伪证据，不删除原失败日志。修正测试预期须有当前版本源码或原模组行为依据，不为使测试变绿降低要求。确认缺陷不能因其他用例通过而关闭。

每轮结果写入覆盖矩阵及运行报告，记录用例ID、精确输入版本、命名空间、命令、退出码、是否正常保存关闭、日志和测试源码哈希、未测边界。累计数按独立用例去重；修正夹具后的回归更新同一用例，不冒充新功能覆盖。

已经通过且输入与相关实现未变的用例不无条件重跑。修复或升级快照后才按受影响范围回归；保留旧提交历史，不把旧99批缺陷自动认定为当前生产仍存在。

最终汇总在全部授权服务端功能测试完成后整理，逐项列出未解决缺陷、依赖问题、已关闭误报和确切未测边界。在此之前，索引明确标记为持续更新，不称全部完成。客户端、Render Preview与Xaero不属于当前服务端轮次。
